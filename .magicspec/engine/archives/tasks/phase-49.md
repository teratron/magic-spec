# Stage 49 Tasks — Planning Split and Stage Boundaries (plan)

**Phase:** 49
**Status:** Done
**Strategic Goal:** The pipeline is four separate stages — spec, plan, task, run — and every invocation performs one: a stage ends by recording what the next needs in the workspace's files and names the next command with its reasoning demand, so a person or a host can switch the model between stages; `goal` alone chains them. `plan` owns the plan and replanning, `task` owns decomposition and hands findings back to `plan` as a directive.
