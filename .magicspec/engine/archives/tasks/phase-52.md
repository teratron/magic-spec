# Stage 52 Tasks — Product Simulation and Interface Design

**Phase:** 52
**Status:** Done
**Strategic Goal:** A consumer project can check its product from the user's side: scenarios written from the specifications while the work is planned, kept current by every task that changes user-facing behaviour, and run by `/magicspec simulate` live or traced (always labelled), every failed step a finding for `/magicspec fix`, carried by the `simulator-tester` role. The developer workflow keeps its own name, so one name means one workflow, and the rule kernel has the room this phase and Phases 53 and 55 need.
