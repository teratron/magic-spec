## Overview

Phase 4 deploys the Prompt Quality Gate (`l1-prompt-quality-gate.md`): the `prompt-engineer` role card (#14) and its five workflow gates. Phase 18 implements the Engine Diagnostics Digest (`l1-engine-diagnostics.md`, `l2-engine-diagnostics.md`): the engine's non-fatal findings stop being written only to a channel the relay contract does not cover, and are delivered once — collected across processes, deduplicated, severity-ordered — immediately before a next step finalization now prints instead of leaving the agent to re-derive. Phase 25 implements a field-confirmed discoverability fix ([l2-finalize-output-contract.md](specifications/l2-finalize-output-contract.md) v1.2.0 §4.5): a report against engine 2.1.73 reproduced the already-documented §4.1 CHANGELOG vocabulary-exhaustion defect, proposing a fix that would have violated RC-11; the real gap is that §4.4's existing `release-changelog` remedy is invisible from `finalize.js`'s own stdout when a bullet gets deduped. Phase 26 implements the code side of the commit-suggestion retirement authored by the `/magic.spec` pass that immediately preceded this planning invocation ([l1-session-continuity.md](specifications/l1-session-continuity.md) v2.0.0 SC-3, [l2-engine-finalization.md](specifications/l2-engine-finalization.md) v3.0.0, [l2-finalize-output-contract.md](specifications/l2-finalize-output-contract.md) v2.0.0): by explicit user directive the engine must no longer compose or print a suggested commit message on any finalize path, and the spec layer already says so — this phase removes the composing functions from `commit-suggester.js`, the flag/config/rendering machinery from `finalize.js`, and the dead config key from both `workspace.json` files, with no design work remaining. Phase 27 deploys the Idea Intake Gate ([l1-idea-intake-gate.md](specifications/l1-idea-intake-gate.md) v1.0.0), authored by the `/magic.spec` pass that immediately preceded this planning invocation on an explicit owner directive: `/magic.spec {idea}` must refine an under-determined idea through clarification before generating specifications, while the agent resolves technical questions itself and phrases any question for a non-specialist. The engine already routes every artifact it *authors* through the `prompt-engineer` quality gate and reviews nothing it *receives* — yet the idea is the first prompt in the chain, and an essence-level defect there is not merely deferred by a `TBD` marker but silently committed by the surrounding prose and inherited by the plan, the tasks, and the code. The phase is reconciliation rather than addition: `.magic/spec.md` presently asserts the opposite rule in three separate places, and planning surfaced the third — the Mode Transition `Auto-Transfer` clause's one-round cap — which the spec's own deployment table had missed. Registration of whitelist entry E6 must land atomically across four surfaces (the DA-2 table, the live constitution, its distributed template, and the ambient user-side rules), since a constitution that disagrees with the engine enforcing it is a release blocker. Phase 28 closes the two engine defects Phase 27 hit in production (retrospective R25, R26), and they are the same defect twice: tooling that reports success while shipping stale output. `workflows/*.md` are hardlinked to `.agents/workflows/*.md` — the tree `sync-skills` actually reads — but the validator hardcodes two groups and the `[C-001]` constraint names one directory, so the wrapper edit delinked the pair invisibly and C14 published a skill wrapper built from pre-edit content. The repair was then blocked by the second defect: change detection reads `.magic/` checksums only, so a `workflows/`-only change reports "No changes detected in engine core" and skips regeneration. The fix binds the regeneration *trigger* rather than widening the checksum manifest, because that exclusion is a deliberate contract protecting user-customizable wrappers and partial installations — a distinction planning established from the source, narrowing a retrospective recommendation that had offered both paths as equivalent.
